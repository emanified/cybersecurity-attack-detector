System architecture

What is a DFA?

A Deterministic Finite Automaton reads an input string one character at a time, transitioning between states according to a fixed table. It accepts if it ends in a marked accept state — no backtracking, no ambiguity, O(n) time.


For cybersecurity, DFAs give exact-pattern matching with zero false positives from probabilistic drift. Each attack signature maps cleanly to a small automaton.

Module breakdown

  • dfa.py — Core DFA class: states, alphabet, transitions, run()
  • classifier.py — Regex pre-filter, routes to each attack DFA
  • attacks/xss.py — 9-state DFA for <script>
  • attacks/sql_injection.py — 10-variant SQL classifier
  • attacks/traversal.py — 4-state DFA for ../../
  • attacks/bruteforce.py — 6-state DFA for 5+ failures
  • gui.py — Original tkinter interface
  • visualizer.py — State graph rendering

Attack detection summary

  • XSS — DFA, 9 states, <script> signature
  • Command Injection — Regex, ; ls / ; cat patterns
  • Directory Traversal — DFA, 4 states, ../../
  • Brute Force — DFA, 6 states, 5+ consecutive failures
  • Phishing — Regex, digit-substituted domain names
  • CSRF — Regex, transfer?amount= endpoint pattern
  • Buffer Overflow — Length check > 200 characters
  • DNS Spoofing — Regex, domain→fake IP pattern
  • Session Hijacking — Regex, duplicate session_token
  • XML Injection — Regex, <role> tag in input
  • SQL Injection — 10 variants, keyword + pattern match

Complexity

  • DFA runs: O(n) single pass, no backtracking
  • Regex pre-filter: O(n), fast early exit for clean input
  • Length check: O(1), checked first
  • Worst case: all classifiers run = O(n) overall
  • Space: O(k) where k = states in largest DFA
  • SQL variants: O(n) per pattern, checked in order
